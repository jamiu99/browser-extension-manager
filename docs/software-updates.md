# 软件更新

右上角「软件更新」显示当前版本和 GitHub 最新正式版。选择「更新并重启」会下载适合系统的包，校验后退出当前窗口，替换应用并重新打开。已随包提供的命令行工具会和应用一起更新。浏览器插件、更新源和浏览器配置继续从各自的本机数据目录读取。

应用使用公开仓库的最新正式 Release。开发预览版只会看到同版本的正式版或更高版本可用。对于无版本号的开发构建，界面给出发布页入口。安装在只读位置时，可从发布页下载并解压到可写目录。

## 发版要求

延用现有 [打包流程](../scripts/package.sh) 和 [发布工作流](../.github/workflows/release.yml)。使用稳定的 `vX.Y.Z` 标签，包括下列发布资源。

- `extension-manager-vX.Y.Z-windows-x64.zip`
- `extension-manager-vX.Y.Z-macos-universal.zip`
- `extension-manager-vX.Y.Z-linux-x64.tar.gz`
- `SHA256SUMS.txt`

包内 `release.json` 提供 `version`、完整 `commit` 和 `builtAt`，并与可执行文件的 `--version` 一致。发布工作流从最终上传的三个安装包生成 SHA-256 校验文件。

更新在安装目录内临时解压。管理器在退出前校验下载包和应用版本，更新进程在原窗口退出后替换应用文件。更新进程会等到新窗口加载完成，才清理原文件。文件替换或窗口启动失败时会恢复原文件并重新打开旧版。如果恢复受安装目录锁定或权限阻止，原文件保留在更新临时目录。
